## E. 风险监控中心 `/risk`

- 目标：让风险在变成事故前被看到；从任何一条风险 2 次点击内建立应急事件。
- `/risk/overview`：顶部 4 卡（高/中/低风险数、今日新增）→ 中部左「风险矩阵图」（影响×概率散点，ECharts）右「按类型分布」→ 底部最新风险 10 条。
- `/risk/list`（主战场）：ProTable。
  - 列：风险编号、等级 Tag（高=红/中=橙/低=蓝，含图标非仅颜色）、类型（供应/物流/需求/质量/库存）、对象（物料/供应商/订单/仓库，可点跳详情抽屉）、风险指数（进度条 0–100，对齐后端库存风险指数）、触发规则、发现时间、状态（新发现/观察中/已建事件/已消除）、操作。
  - 筛选器（LightFilter 常驻 + 高级筛选抽屉）：等级、类型、物料、供应商、订单号、仓库、时间范围、状态。
  - 行操作：**创建应急事件**（主操作，弹确认抽屉：预填风险信息 → 生成 incident 跳详情）、标记观察、忽略（必填理由，记审计）。
  - 批量：合并创建一个事件（多条风险同源时）。
- `/risk/rules`：规则列表（来自阈值配置），开/关 Switch、编辑抽屉（滑杆+数值输入），改动记审计。
- 数据：`risk.ts`：`getRisks(params)`、`getRiskMatrix()`、`createIncidentFromRisks(riskIds)`、`getRules()/updateRule()`（后端 inventory_monitor / supply_monitor / thresholds.yaml）。

## F. 应急事件详情页 `/incident/:id`

- 目标：一页看全「发生了什么、影响多大、现在到哪一步、谁负责」。
- 布局：
  - 头部：事件编号+标题、类型 Tag（5 类中断事件，对齐后端 port_shutdown 等）、风险等级、状态条（PageHeader + StepsProgress：发现→评估→方案→审批→执行→复盘）、责任人（头像，可改，权限内）、创建时间/来源风险。
  - 头部右侧操作：生成决策方案（主按钮，跳 G）、升级/降级等级（scm_lead+）、关闭事件（需复盘小结）、添加备注。
  - 主体左 70%，Tabs：
    - **影响范围**（默认）：受影响物料表 / 受影响订单表（订单号、客户、客户等级🔒、承诺交期、缺口量、预计延误天数）/ 受影响库存（仓库、当前量、可支撑小时数）/ 涉及供应商卡片（状态、替代供应商数）。
    - **时间线**：Timeline 组件，系统事件+人工备注混排（发现、升级、方案生成、审批、任务完成…），支持插入备注和附件。
    - **关联方案**：该事件的全部方案版本列表（含被驳回版本）。
    - **任务**：拆解出的任务表（联动 I）。
    - **操作记录**：该事件的审计日志切片。
  - 右侧 30% 信息栏：当前状态摘要卡、关键数字（预计损失、已投入应急成本）、参与人列表、附件区（上传/下载）。
- 数据：`incident.ts`：`getIncident(id)`、`getImpact(id)`（后端 economic_impact）、`getTimeline(id)`、`updateIncident()`、`closeIncident()`。

## G. 决策方案生成页 `/decision/generate/:incidentId`

- 目标：把多 Agent 输出变成「人能比、能改、能拍板」的方案对比页。这是本产品差异化核心页，必须精细打磨。
- 布局（自上而下）：
  1. 事件摘要条（可折叠）。
  2. **生成过程区**：点击「生成方案」后展示 Agent 工作流水（采购 Agent / 物流 Agent / 财务 Agent 依次亮起，展示各自要点结论，对齐后端 PayoffModel+DebateEngine；mock 用 2–3 秒定时器模拟流式）。完成后折叠为一行「查看推演过程」。
  3. **方案对比区**（核心）：横向 2–4 张方案卡：
     - 卡头：`推荐` 金色角标 / `备选` 灰标 / `不可行` 置灰卡（折叠在"查看不可行方案(n)"里，展开显示不可行原因，如违反约束）。
     - 卡身四大对比指标（每卡同序）：总成本（¥，环比基线 +/-）、交期影响（天）、剩余风险（低/中/高）、客户影响（受影响订单数/高等级客户数）。
     - 五视角折叠面板：采购/物流/财务/销售/生产 各自明细（该视角的动作、量、价、备注）。
     - 卡底：「AI 解释」折叠区——为什么推荐/不推荐，引用证据（历史经验卡片编号、约束项），对齐后端 DecisionExplainer；解释放卡内而非全局，保证"看着方案读理由"。
  4. 对比表模式切换：卡片视图 ⇄ 指标对比表（行=指标，列=方案，差异高亮）。
- 人工修改：方案卡「调整」按钮 → 右侧抽屉，可改：供应商选择（下拉替代供应商）、采购量、运输方式、分批比例。改动后指标标记「已修改，待重算」→「重算」按钮调用 `recalc()`，返回新指标并保留修改人痕迹。
- 底部操作条：选中一张卡 →「提交审批」（生成审批单，跳 H）/「保存草稿」。
- 数据：`decision.ts`：`generateProposals(incidentId)`、`recalc(proposalId, overrides)`、`getExplanation(proposalId)`、`submitForApproval(proposalId)`（后端 orchestrator / constraint_solver / explainer / feedback）。

## H. 审批页 `/decision/approval` + 审批详情

- 目标：审批人**不离开本页**就能获得拍板所需全部信息。
- 列表：待我审批（默认 tab）/ 我已审批 / 抄送我。列：审批单号、事件、风险等级、方案摘要、成本影响¥、提交人、等待时长（超时红字）。
- 详情（抽屉或整页，>1200px 用整页）：
  - 上：决策摘要卡——风险等级、总成本及对预算影响、客户影响（几个订单、什么等级客户、延误几天）、系统推荐理由（3 条以内 bullet）+「查看完整推演」链接回 G 只读模式。
  - 中：方案对比精简表（本方案 vs 基线不作为 vs 次优方案，三列）。
  - 下：审批链进度（Steps：谁已批/待谁/会签状态）+ 历史审批意见。
  - 操作条：**批准**（绿）/ **驳回**（必填理由）/ **要求重算**（填调整方向，回到 G 携带意见）/ **转交**（选人+理由）。均二次确认。
  - 审批意见沉淀：批准/驳回时可勾选「存为经验」→ 意见+方案快照写入经验卡片库（后端 experience_cards / learning.py），在 K 案例库可检索。
- 数据：`approval.ts`：`getApprovals(tab)`、`getApprovalDetail(id)`、`approve/reject/recalcRequest/transfer`。

## I. 执行任务页 `/task`

- 目标：方案批准后自动拆成可跟踪的任务，谁的任务谁清楚，超时有人管。
- 拆解规则（前端展示，拆解逻辑 mock）：方案批准 → 按视角生成任务：采购任务（下单/催货）→ buyer；物流任务（改线/加急）→ scm_lead 或指定；客户沟通任务 → sales；库存调整任务（调拨/冻结）→ warehouse；生产调整 → planner。每任务含：标题、来源方案、负责人、截止时间、优先级、检查项 checklist。
- `/task/mine`：卡片看板（待办/进行中/已完成 3 列拖拽）+ 列表切换。任务卡：倒计时（临期橙/超时红）、来源事件链接、一键完成（有 checklist 则需全勾）。
- `/task/all`（scm_lead/boss）：ProTable 全量 + 按事件分组视图；改派操作。
- `/task/overdue`：超时看板，按负责人聚合柱状图 + 超时明细；「催办」按钮发通知。
- 超时提醒：截止前 2h 站内信；超时即通知负责人+上级；通知服务统一走 `notify.ts`（预留 webhook）。
- 数据：`task.ts`：`getTasks(scope)`、`updateTaskStatus()`、`reassign()`、`urge()`。

## J. 数据导入页 `/data/import`

- 目标：小企业把 Excel 扔进来就能用，错了知道怎么改。
- 流程 Steps（5 步）：
  1. 选类型（物料/供应商/客户/订单/库存）+ 下载标准模板按钮。
  2. 上传：Dragger，xlsx/csv，≤10MB；上传后前端解析（SheetJS）预览前 20 行。
  3. **字段映射**：左列=文件表头，右列=系统字段下拉（自动按名称相似度预匹配，置信度低标黄）；必填字段未映射不可下一步；「保存为映射模板」供下次复用。
  4. 校验预览：全量校验（必填缺失/类型错误/枚举非法/重复行），错误行内联标红 + 错误汇总侧栏（按错误类型分组，点击定位）；重复数据策略 Radio：跳过/覆盖/合并。可「仅导入正确行」。
  5. 结果报告：成功 n 条 / 失败 m 条，失败明细可下载「错误报告.xlsx」（原行+错误原因列）修复后重传。
- 导入历史 tab：批次列表（时间/类型/成功失败数/操作人/回滚按钮——仅当日批次可回滚）。
- 数据：`import.ts`：`parseFile`、`getFieldMapping(type)`、`validateRows`、`commitImport`、`getImportHistory`、`rollback`（后端 enterprise_ingest / import_preflight / streaming_import）。

## K. 自定义字段与表单配置页 `/settings/fields`

- 目标：小企业能自己加字段，但系统不失控。
- 允许自定义的对象：物料、供应商、客户、订单（库存/任务不允许）。每对象自定义字段上限 **20 个**，超限提示。
- 字段类型（第一期仅 6 种）：单行文本、数字、日期、单选、多选、金额。不做公式/关联/子表。
- 每字段可配置项：名称、类型、是否必填、**是否参与风险计算**（打开后要求选映射到哪个风险因子，仅数字/金额/日期可开）、是否在列表页默认显示、是否敏感（进入字段权限体系）。
- 防混乱机制：系统字段不可删改（锁图标）；自定义字段停用而非删除（历史数据保留）；改类型禁止（只能停用重建）；每次变更记审计；预览区实时显示表单效果。
- 数据：`fields.ts`：`getFieldSchema(objectType)`、`saveField`、`disableField`。列表页与详情页渲染必须消费同一 schema（动态列/动态表单封装 `<DynamicField/>`）。

## L. 报表看板页 `/report`

- `/report/executive`（老板）：本月风险事件数及同比、应急总成本 vs 避免损失（**系统价值主数字：避免损失-应急成本=净收益**）、平均响应时长（发现→批准→执行完成）、Top 风险供应商、高等级客户履约率。大数字+趋势线，≤8 个图。
- `/report/operation`（供应链负责人）：风险类型分布与趋势、事件处理漏斗（发现→建事件→出方案→批准→完成）、任务超时率按部门、库存周转与安全库存达标率、供应商交期达成率排名。
- `/report/response`（应急效果）：每事件复盘卡：响应时长分解（各阶段耗时条形）、方案预估 vs 实际（成本/交期偏差）、经验卡片产出数。量化口径页内固定说明（Tooltip 注明计算公式），对齐后端 value_dashboard / automation_stats。
- 通用：时间范围筛选、导出 PNG/CSV（有导出权限者）、ECharts、图表配色遵守 05 文档。
- 数据：`report.ts`：`getExecutiveReport(range)`、`getOperationReport(range)`、`getResponseReport(range)`。
