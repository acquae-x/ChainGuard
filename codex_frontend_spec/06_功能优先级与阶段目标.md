# 06 功能排布优先级（§17）

## 排序逻辑

排序依据三条：①没有它企业无法开始用（准入项）；②它是本产品的差异化价值（应急决策闭环）；③它可以后补而不伤信任（增效项）。P1 = 准入 + 核心价值闭环「数据进得来 → 风险看得见 → 方案出得来 → 人能拍板 → 有据可查」；P2 = 让第二周还愿意用；P3 = 让它变成行业产品。审计记录进 P1 而非 P2，因为企业采购供应链决策系统时"可追责"是信任前提，不是增值功能。

## P1 第一优先级（MVP，Codex 本次必须完整生成）

范围：注册登录、企业空间与初始化向导、基础数据导入、风险监控、应急事件、方案推荐、人工审批、审计记录。

前端完成度要求：
- 对应页面：A/B/C/D/E/F/G/H/J + 用户/角色管理 + 审计日志页。
- 全部真实交互（表单校验、状态流转、权限控制生效），数据走 mock 服务层。
- **精细打磨**（高保真+完整状态）：登录/注册、初始化向导、工作台、风险列表、事件详情、**方案生成页（G，全项目最高优先）**、审批页、数据导入。
- 演练数据：mock 内置演示租户，含 1 个完整跑通的 supplier_shutdown 案例（风险→事件→3 方案→审批→任务→复盘），保证任何人 clone 后 `npm run dev` 即可走完全流程。

## P2 第二优先级（生成骨架，允许低保真）

范围：任务执行跟踪（I）、报表看板（L）、角色权限精细化（数据/字段权限配置界面）、自定义字段（K）、通知提醒中心、历史经验库（案例库页）。

前端完成度要求：页面与路由全部建出，核心表格/表单可用，mock 数据可展示；看板图表可先用 3–4 个核心图；通知先做站内信下拉；不要求全部四态打磨。原因：这些功能依赖 P1 产生的数据沉淀，第一批用户前两周主要在跑 P1 闭环。

## P3 第三优先级（本次只留扩展点，不生成页面）

范围：ERP 对接、OCR 单据识别、移动端/小程序、智能预测、行业模板市场、多企业协同。

前端要求：只做三件事——①`services/` 接口层按可替换设计（switch mock/real）；②系统设置放「集成」占位菜单（灰色 + "即将上线"）；③通知层预留 webhook 配置结构。不写任何 P3 页面代码。原因：均依赖外部系统或数据积累，提前做只会增加维护面。

## 阶段验收口径

- P1 验收：新企业从注册到完成一次示例演练 ≤ 10 分钟；9 个演示账号登录后菜单/按钮/字段权限与 02 文档矩阵一致；审计日志能查到演练全过程记录。
- P2 验收：方案批准后自动生成任务并可流转；老板看板能算出"净收益"数字。
