# 01 注册登录与企业初始化（§12）

> 本文档是 Codex 生成代码的直接依据。所有页面路由、字段名、组件选型均为强约束，不得自行更名。
> 技术栈：React 18 + Ant Design Pro（ProComponents）+ TypeScript。数据一律走 `src/services/` 统一 API 层，当前用 mock 实现，接口签名对齐后端 FastAPI（ChainGuard/src/api.py），后续替换 baseURL 即可切真实后端。

## 1. 账号体系总原则

- 多租户 SaaS：一个企业 = 一个租户（tenant）= 一个工作空间。用户属于且仅属于一个租户（预留 userId↔tenantId 多对多的数据结构，但 UI 第一期不做切换器）。
- **只有两个入口能产生新用户**：①企业注册（产生该租户的第一个管理员）；②企业内邀请/管理员创建。不存在游离于企业之外的个人注册。
- 普通员工**永远不走注册页**：他们通过「邀请链接/邀请码」或「管理员预建账号+初始密码」进入。注册页只面向企业管理员/老板/供应链负责人这类"建空间的人"。

## 2. 注册流程（路由 `/user/register`）

三步完成，每步一屏，顶部 Steps 步骤条。**总填写字段 ≤ 10 个**，其余全部初始化向导里补。

**第 1 步 账号验证**
- 字段：手机号（必填，+86 校验）、短信验证码、密码（8 位以上，强度条）。邮箱为可选备用项（tab 切换"邮箱注册"）。
- mock：验证码固定 `123456`，服务层留 `sendSmsCode(phone)` / `verifySmsCode(phone, code)` 接口。

**第 2 步 企业信息**
- 字段：企业名称（必填，支持模糊联想，mock 返回工商名录假数据）、行业（必填，Select：电子制造/汽车零部件/食品饮料/医药/日用消费品/机械设备/其他）、企业规模（Radio：<50 人 / 50–200 / 200–1000 / >1000）、您的角色（Select：老板/总经理、供应链负责人、IT 管理员、其他）。
- 不采集：注册资本、统一社会信用代码、详细地址——这些放到系统设置里补填，注册时一律不问。

**第 3 步 开通方式**
- Radio 卡片二选一：`免费试用 30 天`（默认选中，无需付款信息）/ `我有企业授权码`（输入框）。
- 部署方式仅展示说明文案「当前为云端 SaaS 版，私有化部署请联系我们」，不做分支逻辑。
- 提交后：创建 tenant + 第一个用户（角色自动=企业管理员），写入 `tenantStatus: 'initializing'`，跳转 `/onboarding`。

**「加入已有企业」入口**：注册页第 1 步下方常驻链接「已有同事在用？通过邀请码加入」→ `/user/join`，输入 8 位邀请码或粘贴邀请链接 → 校验通过后只填：姓名、手机号、验证码、密码（角色由邀请时指定，不可自选）→ 直接进工作台，不进初始化向导。

## 3. 登录（路由 `/user/login`）

- Tab 1 账号密码：手机号/邮箱 + 密码；「记住我」7 天；连续 5 次失败出图形验证码，10 次锁定 15 分钟（mock 层模拟状态即可）。
- Tab 2 验证码登录：手机号 + 短信码。
- 辅助链接：忘记密码（`/user/reset`：手机号→验证码→重设）、企业邀请码入口（跳 `/user/join`）、免费注册。
- SSO 预留：登录卡片底部灰字「企业单点登录（SSO）」入口，点击后弹出「请输入企业域」输入框，mock 返回「该企业未配置 SSO」。服务层留 `getSsoConfig(domain)` 接口，第一期不实现真流程。
- 登录成功路由分发：`tenantStatus === 'initializing'` → `/onboarding`；否则按角色进对应工作台（见 03 文档首页方案）。
- 页面左侧为品牌区：产品名 ChainGuard、一句话定位「供应链中断应急决策系统」、3 条价值点、一张静态截图。**不放营销动画、不放跑马灯数字**。右下角放「体验演示企业」按钮 → 以只读演示租户身份进入（内置演示数据，所有写操作 toast 提示"演示环境不可修改"）。

## 4. 租户/组织模型（前端 TypeScript 类型，mock 与真实后端共用）

```ts
Tenant { id; name; industry; scale; status: 'initializing'|'active'|'expired'; plan: 'trial'|'paid'; trialEndAt }
Department { id; tenantId; name; parentId }        // 树形，默认给：采购部/仓储部/销售部/财务部/生产部
User { id; tenantId; name; phone; email?; deptId; roleIds: string[]; status: 'active'|'invited'|'disabled' }
Role { id; tenantId; code; name; builtin: boolean } // 内置角色见 02 文档，允许租户自建角色
Invitation { id; tenantId; code; roleId; deptId; expireAt; maxUses; usedCount }
```

## 5. 首次初始化向导（路由 `/onboarding`，共 6 步）

设计铁律（防劝退）：
- **每一步都有「跳过」**（第 1 步除外），跳过即用默认值；右上角常驻「稍后再说，直接进入系统」。
- 全程可完成时间 ≤ 5 分钟；每步只做一件事；进度自动保存（localStorage 不可用 → 用内存 state + mock 服务端保存 `onboardingProgress`）。
- 跳过的步骤在工作台首页显示为「待办卡片」（如"还未导入供应商数据 → 去导入"），逐步引导补齐，而不是一次逼完。

| 步 | 内容 | 默认值/跳过行为 |
|---|---|---|
| 1 | **选行业模板**：卡片单选（与注册行业联动预选中），模板决定：物料字段模板、风险规则默认阈值、示例数据 | 不可跳过，默认选注册时行业 |
| 2 | **选业务模块**：Checkbox 卡片：风险监控✓、应急决策✓、库存管理✓、订单管理✓、供应商管理✓、物流管理□、报表□。打勾即出现在左侧菜单 | 默认前 5 项开启，可跳过 |
| 3 | **导入基础数据**：四个 tab（物料/供应商/客户+订单/库存），每个 tab 提供 ①下载 Excel 模板 ②上传导入（复用 10.数据导入页组件）③「先用示例数据」按钮 | 跳过 = 自动灌入行业模板示例数据，并全局标记 `demoDataFlag`，页面顶部黄条提示"当前为示例数据" |
| 4 | **配置风险阈值**：只暴露 3 个滑杆——安全库存预警线（默认 20%）、交期延误容忍天数（默认 3 天）、单一供应商依赖占比上限（默认 60%）。高级阈值（config/thresholds.yaml 对应的完整参数）折叠进"高级设置"，默认不展开 | 跳过 = 用行业模板默认值 |
| 5 | **邀请成员**：批量输入手机号 + 选角色（默认"采购人员"）→ 生成邀请码/链接；或"复制邀请链接到微信群" | 可跳过 |
| 6 | **示例应急演练**：一键触发内置 `supplier_shutdown` 演练事件（数据来自行业模板），引导用户走一遍：看到风险告警 → 打开事件 → 查看多 Agent 方案 → 点一次"批准"。完成后弹结果页：「你已完成第一次应急演练，系统已生成你的风险监控看板」→ 进入工作台 | 可跳过，工作台保留"开始演练"入口 |

**默认配置策略（哪些先不配）**：审批流默认单级（企业管理员审批一切）；部门默认 5 个标准部门；字段默认行业模板全集；通知默认站内信；数据权限默认全员可见本部门。以上均在系统设置中可改，向导一律不出现。

## 6. Codex 实现要求

- 路由：`/user/login`、`/user/register`、`/user/join`、`/user/reset`、`/onboarding`。user 布局用 Ant Design Pro 的 UserLayout。
- 状态：注册/向导数据存 zustand 或 useModel（Pro 自带），不用 redux。
- 校验：全部用 antd Form rules，手机号正则 `^1[3-9]\d{9}$`。
- mock：`mock/user.ts`、`mock/tenant.ts`，登录返回 JWT 假 token + 当前用户（含角色、权限码数组），存入全局 initialState。
- 所有接口签名写在 `src/services/typings.d.ts`，注释标注「对接后端时的真实 endpoint」。
