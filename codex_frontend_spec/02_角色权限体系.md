# 02 企业权限与角色体系（§13）

> 前端按「权限码（permission code）」控制一切可见性与可操作性。后端最终裁决，前端负责隐藏/禁用。权限码由登录接口随用户返回（`currentUser.permissions: string[]`），菜单/按钮/字段三层全部消费同一套码。

## 1. 内置角色（9 个，租户内可复制修改，不可删除内置项）

权限码命名规则：`模块:资源:动作`，如 `risk:event:create`、`data:supplier:export`、`field:cost:view`。

| # | 角色 code | 角色名 | 定位 |
|---|---|---|---|
| R1 | `admin` | 企业管理员 | 管账号、权限、系统配置，不一定懂业务 |
| R2 | `boss` | 老板/总经理 | 看全局、批大事，操作极少 |
| R3 | `scm_lead` | 供应链负责人 | 业务第一责任人，日常审批主力 |
| R4 | `buyer` | 采购人员 | 处理采购任务、维护供应商 |
| R5 | `warehouse` | 仓库人员 | 库存录入盘点、执行库存任务 |
| R6 | `sales` | 销售/客服 | 看订单风险、执行客户沟通任务 |
| R7 | `finance` | 财务人员 | 看成本影响、确认资金相关方案 |
| R8 | `planner` | 生产计划人员 | 看物料齐套风险、调整生产计划任务 |
| R9 | `auditor` | 只读审计 | 全局只读 + 审计日志，零写权限 |

## 3. 数据权限（行级）

- 维度：部门、仓库、客户、供应商、物料类目。用户绑定「数据范围」：`all`（全部）/ `dept`（本部门及子部门）/ `custom`（勾选具体仓库/客户/供应商/类目清单）。
- 默认：R1/R2/R3/R7/R9 = all；R4 = 自己负责的供应商+类目；R5 = 所属仓库；R6 = 自己负责的客户；R8 = 负责的物料类目。
- 前端实现：所有列表请求自动带 `scope` 参数；mock 层按 scope 过滤。无权数据**不出现**（而不是置灰）。
- 配置界面在「权限管理→数据权限」：按用户/角色分别设置，表格 + 抽屉勾选。

## 4. 字段权限（列级脱敏）

- 敏感字段注册表（前端常量 `SENSITIVE_FIELDS`）：`cost`（成本单价/总成本）、`profit`（毛利/利润率）、`contract`（合同金额/条款附件）、`customerLevel`（客户等级）、`supplierPrice`（供应商报价）。
- 无对应 `field:*:view` 码时：表格列显示 `***`，详情页显示 `***` + 锁图标 + Tooltip「无权限查看，请联系管理员」；导出文件中该列同样脱敏；图表中不参与聚合展示（图例置灰）。
- 组件要求：封装 `<SensitiveField field="cost" value={...}/>` 统一处理，禁止各页面手写。

## 5. 审批权限（按风险等级路由）

| 事件风险等级 | 审批链（默认，可在系统设置改） | 超时升级 |
|---|---|---|
| 低（L1） | 供应链负责人 单人批 | 4h 未批 → 提醒 |
| 中（L2） | 供应链负责人 → 财务会签（仅当方案成本影响 > 阈值，默认 ¥50,000） | 2h 未批 → 抄送老板 |
| 高（L3） | 供应链负责人提交 → 老板/总经理终批，财务并行会签 | 1h 未批 → 短信/电话（预留通知接口） |

- 审批动作：批准 / 驳回（必填理由）/ 要求重算（回到方案生成页并携带审批意见）/ 转交他人（选人，留痕）。
- 审批链配置页：系统设置→审批流，第一期只做「按风险等级选审批人」的简化配置，不做可视化流程编排器。

## 6. 操作审计

- 记录范围：登录/登出、查看敏感字段（触发 `field:*:view` 的明文展示时记一条 view 日志）、增删改基础资料、创建事件、方案修改、每一次审批动作、导入/导出、权限变更。
- 日志结构：`AuditLog { id; time; userId; userName; roleCode; action; targetType; targetId; targetName; detail(diff JSON); ip }`。对齐后端 `src/audit.py` 的 JSONL 结构。
- 页面：「系统设置→审计日志」，ProTable：时间范围 + 操作人 + 动作类型 + 对象类型筛选；detail 列点开抽屉显示变更 diff（旧值→新值，红绿对比）。仅 admin / auditor / boss(只读) 可见。
- 导出：auditor 可导出 CSV。

## 7. Codex 实现要求

- 用 Ant Design Pro 的 `access.ts` 插件：`canXxx` 全部由 `currentUser.permissions` 派生；菜单 `access` 属性 + 按钮 `<Access accessible={...}>` 双层控制。
- 角色管理页（`/settings/roles`）：左侧角色列表（内置角色带"内置"标签）、右侧权限树（按 模块→页面→按钮/字段 三级 checkbox）。内置角色只读，需修改则「复制为自定义角色」。
- 用户管理页（`/settings/users`）：ProTable + 新建用户抽屉（姓名/手机号/部门/角色/数据范围）、批量邀请入口、启用/停用。
- mock 提供 9 个角色各 1 个演示账号（密码统一 `Demo@1234`），登录页演示企业模式下可一键切换角色体验。
