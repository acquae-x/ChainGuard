# 缺失功能融入设计（用户视角，按页面组织，2026-07-12）

以 08 对照为底，回答"每个缺失能力融进现有哪个页面、什么位置、用户看到什么"。编号沿用 08。实现批次标注在括号。

## 1. 方案生成页（scm_lead 的决策心脏，改动最大）

现状：3 张方案卡（成本/交期/客户影响/剩余风险）+ 五视角明细 + 简版"AI 解释与证据"。

融入：

- **方案间冲突提示（A06，5A）**：卡片区顶部加一条冲突横幅——引擎检测到方案冲突时显示"⚠ 采购与物流方案存在资源冲突"，展开看冲突原因。无冲突不显示。用户价值：选方案前先知道哪些不能并行。
- **"查看完整推演"实体化（A06–A08/A10/A12，5A E-1 核心）**：方案生成页与审批页共用一个**完整推演抽屉/子页**（审批页那个死链接就是入口），按决策过程分四段渲染：
  1. 评分与冲突——各方案总分构成、冲突检测结论
  2. 辩论过程——谁反驳谁、论点摘要（rebuttal 数据）
  3. 仲裁结论——选了谁、推导链（arbitration + 推导过程）
  4. 约束分析——违反了哪些约束、**推荐调整**（可操作建议列表，如"首批比例降至 40% 可解除资金约束"）
  用户价值：从"系统给了三个方案"变成"我能看懂系统为什么这么推荐"——这是应急决策系统敢被信任的关键。
- **AI 解释升级（A12，5A）**：方案卡的解释区从 evidence 列表改为三层：一句话结论 → 关键因素（带权重）→ 证据链。
- **历史经验角标（A11，5B）**：方案卡右上"📎 引用 2 条历史经验，置信度 +12%"，点开显示经验卡摘要。用户价值：知道这个建议有没有前车之鉴背书。

## 2. 审批页（boss/finance 的拍板现场）

- **执行确认点清单（A14，5A）**：决策摘要下方加"执行确认点"卡片，逐条列出引擎产出的 `manual_confirmation_points`：`[采购] 与宁波微电确认 6000 件现货──跳过风险：到货延误 3 天`。批准弹窗加勾选"上述确认点已逐项核对"。不阻塞（阻塞语义已由会签承担），是给拍板人的核对清单。用户价值：boss 30 秒看清"批之前该打哪几个电话"。
- **决策审计（A13，5A，随 F5）**：页面底部"查看决策审计记录"抽屉——decision_id、完整推导 JSON、时间戳，审计人员可下载。
- **导出决策报告（A15，5A）**：右上角"导出报告"，JSON 先行（内容=完整推演+确认点+审批链），给线下汇报/存档用。

## 3. 导入向导（admin 的数据入口）

- **容量预检结构化（D02，5A）**：第 4 步顶部把原始 JSON 换成三件套——
  结论徽标：✅ 容量预检通过 / ⚠️ 数据量较大，建议评估 PostgreSQL / ⛔ 磁盘空间不足，导入已阻止；
  两个数字：当前磁盘余量、本批预计增量；
  消息列表：逐条预检发现。⛔ 时"仍要导入"按钮禁用（后端本就会拒）。
- **归一化预览（D03，5A）**：第 4 步的数据表格从"浏览器 SheetJS 解析原文件"改为"服务端归一化结果"（表名+行数+前 N 行），与最终落库的东西一致。用户价值：预览即所得，消除 A1 曾经的"预览过、落库拒"错觉的最后残余。
- **重复批次警告（D04，5B）**：预检卡片加一行"与 2026-07-10 批次内容重复度 93%，疑似重复导入"，附"确认覆盖"选项。

## 4. 事件详情（scm_lead 的作战室）

- **风险解释（A03，5B）**：关联风险卡片加"为什么预警"展开——触发规则、当前值 vs 阈值、趋势。依赖 C2 实时计算。
- 影响范围完整版（A04 完整体，5B）：物料/订单/供应商/库存四表真实数据填充（现为尽力匹配版）。

## 5. 工作台与报表（boss 的驾驶舱）

- **价值仪表盘（C04，E-4，可与 5A 并行）**：报表看板"高管报表"页三块——本次事件净收益（避免损失-应急成本）、累计避免损失时间线、决策提速对比（传统流程 vs 系统辅助）。用户价值：老板续费的理由。
- 节点健康图（C02/C03，5B）：工作台加供应链节点健康卡；一线角色工作台显示"我的节点"明细。

## 6. 个人与账户（所有角色）

- **个人设置落地（F01，5A）**：顶栏头像菜单"个人设置"从 toast 变成真实页——修改密码（校验旧密码；成功后作废刷新 cookie 强制重登）。
- **管理员重置密码（F02，5A）**：系统设置→用户管理行操作加"重置密码"→ 弹出一次性临时密码，该用户首登强制改密。
- **忘记密码（F03，5A 过渡）**：登录页死链接改为提示"请联系企业管理员重置"；Phase 6 再做自助。

## 7. 通知铃铛（所有角色，D3，5A）

用户视角的变化：铃铛从"只有审批待办"变成——任务分派到我 / 有人催办 / 会签请求 / 超时自动放行提醒 / 导入完成或失败 / 高风险预警（按 05 清单 D3 矩阵）。同类 5 分钟聚合，避免轰炸。

## 8. 系统设置 → 集成（admin，Phase 6）

ERP 集成页（E01/E02）：连接配置（URL/凭证）→ 测试连通 → 表目录预览（catalog）→ 字段映射确认 → 手动同步 + 同步历史列表。占位入口现在就有（灰色"即将上线"），Phase 6 点亮。

## 9. 报表看板 → 决策质量（分析师/管理员，Phase 6）

敏感性曲线（B01）、模型对比评测（B02）、漂移体检（B03）、Pareto 前沿（A10 附属）集中放"决策质量"页——面向想审视"系统靠不靠谱"的高级用户，不打扰主流程。

## 汇总：5A 的用户可感知变化清单（验收视角）

做完 5A，用户能感知到的新东西：①方案页能看懂"为什么推荐"（完整推演四段）；②审批页有确认点清单和导出；③导入预检从 JSON 变成红绿灯；④预览即所得；⑤能改密码、管理员能重置密码；⑥铃铛通知覆盖任务/会签/导入。——共 6 项，条条对用户可见，作为 5A 验收口径。
