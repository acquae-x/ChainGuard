# ChainGuard Phase 5A 界面实测报告

执行时间：2026-07-13（Asia/Shanghai）

本报告只记录本次在真实 ChainGuard 前端中的实际操作结果。前端地址为 `http://127.0.0.1:8081`，API 地址为 `http://127.0.0.1:8000`；为避免污染默认开发数据，使用隔离数据库 `ChainGuard/phase5a_ui_audit_20260713.db`。本轮没有修改业务代码。

## 结论

Phase 5A 当前不满足界面验收关闭条件。登录、通知聚合、高风险审批主链、财务会签后任务拆解、超时扫描与通知直达能够工作；但追认动作实际不可提交、审批页 375px 响应式失败、XLSX 归一化预览为空、推演图表被原始 JSON 挤到页面深处、生成决策指标为零/缺失、PDF 导出在当前运行环境返回 500。另发现种子审批悬空、老板终批跳转错误、会签完成步骤未刷新及管理员菜单/权限不一致。

## 逐流程实测

| # | 流程 | 结果 | 实际观察 |
|---|---|---|---|
| 1 | 登录与角色切换 | 通过 | SCM、boss、finance 均可用账号密码登录；退出后可切换角色。 |
| 2 | 工作台与风险总览 | 部分失败 | 工作台可打开；风险总览中的风险矩阵和类型分布图几乎为空，仅见坐标/细线，无法支撑判断。 |
| 3 | XLSX 导入向导 | 失败 | 红绿灯显示“容量与格式预检通过”，但预估行数为 `—`，后端把 16.07KB XLSX 估为约 31 行，归一化预览显示无数据行。 |
| 4 | 决策生成与完整推演 | 部分失败 | 推演结果已持久化并能打开；第 4 节先输出约 3,600 字符原始 JSON，Pareto/敏感性图被推到很深的位置。生成方案的总成本、交期、客户影响均为 0，剩余风险为“数据缺失”。 |
| 5 | 审批提交通知 | 通过 | SCM 提交后，boss 的“待我审批”和铃铛通知中均出现审批；finance 收到待会签通知。 |
| 6 | boss 终批 | 部分失败 | 终批成功并进入 `pending_countersign`；随后错误跳转到 `/task/all`，当时任务表为空，容易让用户误以为审批已生效。 |
| 7 | finance 会签与任务拆解 | 部分通过 | 会签成功后实际生成 5 条任务，列表可见；但审批链第 3 步仍显示未完成，页面状态没有与成功结果同步。 |
| 8 | 超时自动放行与通知 | 通过 | 在隔离库构造 `ap-timeout-ui` 的待会签超时状态，实际调用扫描器返回 `released=1`；finance 铃铛出现追认通知，点击可直达审批详情。 |
| 9 | 追认通过/追认异议 | 阻断失败 | 页面显示两个动作，异议空理由会被前端拦截；填写理由后 API 返回 409“审批单已处理”，前端进一步抛出整页 `Unhandled Rejection`。后端通用状态检查在追认分支之前拒绝 `approved` 状态，因此两个追认动作均无法落库。 |
| 10 | 375px 审批页 | 失败 | viewport 为 375px 时文档宽度实测 584px，横向溢出 209px；之前一次审批页测量为 561px。审批详情和底部动作存在裁切。完整推演抽屉自身宽 375px，但第 4 节仍展示大段原始 JSON。 |
| 11 | 角色字段脱敏 | GET/JSON 通过 | 同一 decision-detail 中，buyer 的成本权重与方案成本均为 `***`；boss 对应值分别可见（例如 0.2、68.97、33.33、66.67）。 |
| 12 | PDF 导出 | 当前环境失败 | buyer 与 boss 的真实 PDF 导出请求均返回 `CG-5000`。运行服务所用 Python 缺少 `reportlab`；依赖已写入 `requirements.txt`，但当前服务环境未安装，因此没有生成可供截图的真实 PDF，也未把该项标记为通过。 |
| 13 | 管理员审批入口 | 失败 | 管理员能看到“审批中心”菜单，但进入后显示无操作权限；现有管理员权限与菜单可见性不一致。 |

## 可用性与无障碍观察

正向项：登录输入有可访问名称；主要操作按钮、抽屉关闭按钮和通知标签可由语义定位；表格存在列标题；导入红绿灯同时提供文字，不只依赖颜色。

风险项：375px 横向溢出会导致键盘/放大用户难以访问右侧动作；追认错误覆盖全页且没有可恢复的业务提示；原始 JSON 对阅读、屏幕放大和认知负担都不友好；空图表缺乏替代摘要；完成状态仍用未完成步骤表达，会误导依赖状态文本的用户。

本轮未执行完整屏幕阅读器、全键盘路径、自动对比度和浏览器缩放矩阵测试，因此这些项目不能声明通过。

## 建议修复优先级

1. P0：把追认分支移到通用“审批单已处理”状态检查之前，并在前端捕获 409 显示业务错误，补 UI/API 回归。
2. P0：修正审批详情数据映射，禁止将未知成本、交期、风险静默渲染为 0；同时修复会签完成步骤刷新。
3. P1：修复 375px 审批详情布局，确保文档宽度不超过 viewport；将方案对比改为可横向滚动的局部容器。
4. P1：XLSX 预检必须输出真实工作表行数和归一化预览；解析失败时不得显示绿灯。
5. P1：把 constraint analysis 转成摘要/表格，图表前置；为 Pareto 与敏感性图提供文本摘要和空态。
6. P1：确保运行环境安装 PDF 依赖后，重新实际导出 buyer/boss PDF、渲染 PNG 并比对脱敏字段。
7. P2：修复 boss 终批后的跳转时机、管理员审批菜单权限匹配和悬空种子审批。
