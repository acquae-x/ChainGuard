# ChainGuard 5 分钟操作型演示视频文稿

> 这是一份“边操作、边讲解”的提词脚本。必须先完成当前镜头的操作，看到“画面确认”中的结果后，再念对应旁白。  
> 主线角色：供应链负责人 `scm_lead`；审批角色：企业负责人 `boss`。

## 录制前布置

1. 用浏览器窗口 A 登录供应链负责人，停在“工作台”。
2. 用浏览器窗口 B 登录企业负责人，停在“审批中心”。
3. 两个窗口都提前刷新、预热，避免首次加载出现在成片中。
4. 终端提前进入 `ChainGuard` 目录，但不要预先运行复算命令。
5. 建议使用已播种事件 `INC-20260709-001`；如果编号变化，选择标题为“苏州芯片封测厂停产”的事件。

---

## 镜头 1｜0:00–0:20　开场

**操作指示**

1. 显示标题页 2 秒。
2. 切换到窗口 A 的 ChainGuard 工作台。
3. 鼠标停在页面标题区域，不要立即滚动。

**口播**

> 当供应商停产、港口停运或关键物料延期时，企业需要的不只是一条风险提醒，而是一套能够解释、执行和追溯的应急方案。接下来，我将通过一次真实操作，展示 ChainGuard 如何把风险发现、方案生成、人工审批和审计留痕串成完整闭环。

**屏幕字幕**

`ChainGuard｜供应链中断应急决策系统`

## 镜头 2｜0:20–0:55　查看节点健康

**操作指示**

1. 在工作台向下滚动到“供应链节点健康”。
2. 鼠标依次指向“异常、预警、健康、数据不足”四个计数，各停留约 1 秒。
3. 将“健康状态”筛选为“异常”。
4. 在结果表中横向滚动到“异常原因”列，停留 3 秒。

**画面确认**

- 页面显示四类节点计数。
- 表格显示命中的异常节点及具体原因。
- 若页面提示“样本不足，回退为专家阈值”，不要跳过或遮挡。

**口播**

> 首先看供应链节点健康。系统汇总库存、订单、供应商、运输和外部事件数据，将节点分为异常、预警、健康和数据不足四类。筛选异常节点后，可以看到每条判定对应的观测值、阈值和异常原因。这里展示的不是黑盒标签，而是一组可以逐项核对的事实。

## 镜头 3｜0:55–1:20　说明双轨阈值

**操作指示**

1. 清除“异常”筛选。
2. 鼠标移到表格上方的“判定阈值”说明行。
3. 缓慢指向“绝对红线”“相对离群”“取严”三个关键词。

**画面确认与口播分支**

如果画面显示相对离群线已启用：

> ChainGuard 同时运行两条判定轨道：专家设定的绝对红线，以及从本批数据分布推导的相对离群线，并取更严格的结果。绝对红线负责兜底，相对阈值帮助发现还未触碰红线、但已经明显偏离同类节点的风险。

如果画面显示样本不足：

> 当前租户的有效样本不足，系统明确回退到专家阈值。它不会在数据不够时假装进行数据驱动判断。补充足够的企业数据后，相对离群轨才会启用。

**屏幕字幕**

`绝对红线 + 相对离群｜双轨取严`

## 镜头 4｜1:20–1:55　进入应急事件

**操作指示**

1. 点击左侧“应急事件”。
2. 点击“事件列表”。
3. 找到 `INC-20260709-001 苏州芯片封测厂停产`，点击进入详情。
4. 鼠标沿顶部流程条依次划过“发现、评估、方案、审批、执行、复盘”。
5. 点击来源风险编号，打开风险解释抽屉；停留 2 秒后关闭。
6. 点击右上角“生成决策方案”。

**画面确认**

- 事件详情包含风险等级、责任人、来源风险和影响范围。
- 风险解释抽屉正常加载。
- 最终进入“方案生成与对比”页面。

**口播**

> 现在打开“苏州芯片封测厂停产”事件。顶部流程展示了从发现到复盘的完整状态机。点击来源风险，可以继续追溯事件为什么被触发，以及它影响了哪些物料、订单和业务对象。确认影响后，我们进入方案生成。

## 镜头 5｜1:55–2:35　运行多 Agent 推演

**进入条件**

- 当前账号必须是供应链负责人 `scm_lead@chainguard.demo`。
- 必须从“应急事件 → 事件列表 → 事件详情 → 生成决策方案”进入。
- 不要从“决策方案 → 方案列表 → 查看对比”进入；该入口的网址带有 `readonly=1`，只能查看已有方案。

**操作指示**

1. 确认页面标题是“方案生成与对比”。
2. 如果顶部出现“数据质量”提示，先将鼠标停在提示上；没有提示则直接进行下一步。
3. 在事件摘要下方的白色卡片中央，点击蓝色“生成方案”按钮。
4. 推演动画运行时不要点击，跟随动画讲解。
5. 看到“多 Agent 推演完成”和 3 个候选方案后，停留 2 秒。
6. 展开“查看不可行方案”，将鼠标指向“违反硬约束”说明。

**画面确认**

- 数据质量提示与当前事件一致。
- 页面提示“已生成 3 个候选方案”。
- 方案中包含推荐、备选和不可行项。

**如果没有“生成方案”按钮**

- 直接显示 3 个候选方案：当前处于只读对比页。返回事件详情，点击右上角“生成决策方案”重新进入。
- 显示“当前角色无生成方案权限”：退出当前账号，改用 `scm_lead` 登录。
- 按钮存在但不可点击：页面上方会显示阻断原因；改用已播种的 `INC-20260709-001` 事件，或先补齐提示中的业务数据。

**口播**

> 推演前，系统先检查数据是否足以支撑决策，并明确标出估算字段。点击生成后，采购、物流和财务三个 Agent 分别提出策略，再结合销售和生产约束进行组合仲裁。系统穷举三乘三乘三，共二十七种组合；违反预算、产能或交付硬约束的方案会被直接标出，而不是藏在推荐结果之外。

## 镜头 6｜2:35–3:05　查看完整推演

**操作指示**

1. 点击“查看完整推演”。
2. 在抽屉中依次滚动并停留：
   - 辩论与仲裁结果；
   - “敏感性：库存水平 vs 风险指数”；
   - “策略组合 Pareto 前沿”。
3. 每个区域停留约 3 秒。
4. 关闭推演抽屉。

**口播**

> 点击完整推演，可以回看各方观点、冲突如何收敛，以及最终方案为什么胜出。敏感性曲线展示库存变化对风险指数的影响；Pareto 前沿展示成本与系统效用之间的权衡。系统不只给出一个答案，还保留答案形成的过程。

**屏幕字幕**

`提案 → 约束校验 → 仲裁 → 可解释推荐`

## 镜头 7｜3:05–3:30　选择方案并提交审批

**操作指示**

1. 选择带“推荐”标记的可行方案。
2. 确认页面底部出现“已选择：方案名称”。
3. 点击“提交审批”。
4. 等待“已提交审批”提示出现。
5. 页面跳转到“审批中心”后停留 2 秒。

**口播**

> 现在选择推荐方案并提交审批。ChainGuard 提供建议，但不会替企业自动执行。高风险事件或未收敛方案必须经过人工审批，责任边界被直接写进业务流程。

---

## 镜头 8｜3:30–4:00　负责人批准并生成任务

**操作指示**

1. 切换到已登录企业负责人的窗口 B。
2. 刷新“审批中心”，打开刚提交的待审批方案。
3. 点击“批准”。
4. 如果出现“执行确认点”，逐项检查后勾选“我已逐项核对”。
5. 可勾选“存为经验”，然后确认批准。
6. 等待批准成功提示；若该方案要求财务会签，只展示“待会签”状态，不声称任务已经生成。
7. 审批链全部完成后，点击左侧“任务执行 → 全部任务”。

**画面确认**

- 审批动作成功写入审批链。
- 只有在审批链全部完成后，任务列表才出现执行任务。

**口播**

> 企业负责人可以查看方案依据、成本影响和执行确认点，再决定批准、驳回或要求重算。审批链全部完成后，系统才会把行动拆分给采购、物流、仓储、计划和销售等角色。系统给建议，人负责确认，执行责任不会被算法模糊。

**操作指示**

2. 找到刚才的方案提交和审批记录。
3. 鼠标依次指向操作者、时间、动作和哈希字段。

## 镜头 10｜4:20–4:45　终端现场复算

**操作指示**

1. 切换到已准备好的终端。
2. 输入并执行以下两条 PowerShell 命令：

```powershell
Set-Location "D:\github_projects\Chainguard\ChainGuard"
python -c "from src.benchmark import run_baseline; print(run_baseline())"
```

3. 鼠标依次指向：
   - `inventory_risk_index: 70.25`
   - `feasible_count: 27`
   - `debate_converged: True`

**口播**

> 界面上的关键数字可以现场复算。当前基准场景的库存风险指数是七十点二五，可行组合数是二十七，辩论结果已经收敛。同一份输入会得到同一份结果。大模型只负责组织自然语言，不参与风险计算、约束判断和方案排序。

**操作指示**

1. 切回 ChainGuard 工作台全景。
2. 依次淡入四个关键词：“可解释、可执行、可审计、可人工确认”。
3. 最后 1 秒停留在产品名称上。

## 录制异常备用口径

- **节点健康显示样本不足**：按镜头 3 的“样本不足”分支讲，不得声称相对阈值已经启用。
- **方案页提示估算字段**：正常展示，并说明“系统明确标出数据质量，不隐藏不确定性”。
- **批准后进入待会签**：说“审批进入财务会签”，不要提前说“任务已经生成”。
- **页面加载较慢**：停顿并剪掉等待段，不连续点击按钮。
- **终端复算失败**：停止录制并排查；成片中不使用手工编造的输出。
