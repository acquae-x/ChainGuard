# 效用系数敏感性分析：协调收益对 11 个专家先验权重的稳健性

状态：**已完成，结论进对外口径**
脚本：`python scripts/run_payoff_sensitivity.py --output docs/experiments/payoff-sensitivity.json`
原始数据：`docs/experiments/payoff-sensitivity.json`（621 次求解）
日期：2026-07-27

## 为什么做

协调收益是演示场景的头号对外数字，而它由 `config/risk_weights.yaml` 里 11 个 `payoff_weights` 算出——这 11 个数是**专家先验，没有校准基准**（属于"第三类：结构系数"，见 `defense_qa.md` §10）。所以一个正当的追问是：**这个收益有多少是那 11 个数字的产物？**

此前仓库只有 `src/sensitivity.py`，它单独扫 `current_stock` 对库存风险指数的影响，不覆盖效用系数。本实验补上这一块。

## 先说一条不能回避的结构性事实

**协调收益 ≥ 0 是构造出来的，不是实验发现的。**

自私组合本身就是 27 个组合之一；硬约束只作用于 `coverage_rate` / `estimated_hours` / `cost_multiplier` 这些**参数**，与效用权重无关，所以本场景下 27 个组合恒可行（`feasible_count = 27/27`），自私组合恒在可行集内。而最优值是可行集上的最大值，因此

```
optimal_system_utility ≥ individual_system_utility    恒成立
```

**本分析不能、也不试图证明"协调有益"。**它回答的是另外两个问题：收益的**幅度**是否稳健，以及这个幅度**来自哪里**。

## 基线（当前代码实测）

```
individual_system_utility = 185.59
optimal_system_utility    = 203.84
coordination_gain         = +18.25   (+9.8%)
feasible_count            = 27/27
optimal_combo             = 应急最大化供给 | 最低成本路线 | 盈亏平衡截止
```

> ⚠ **与 `答辩技术详解.md` §9 记载的 183.09 / 195.50 / +12.41（+6.8%）不一致。**当前代码三次连跑均为 185.59 / 203.84 / +18.25，且 `tests/test_webapi.py` 的夹具用的就是 18.25 / 203.84 / 27。旧数字应视为过期记录，需同步更正文档与对外材料。

## 收益归因：18.25 从哪来

| Agent | 自私选择 | 社会最优选择 | Δsystem_utility | 占比 |
|---|---|---|---:|---:|
| 采购 | 多源联合补货 | 应急最大化供给 | +3.76 | 20.6% |
| 物流 | 最快运输优先 | 最低成本路线 | +14.49 | **79.4%** |
| 财务 | 盈亏平衡截止 | 盈亏平衡截止 | 0.00 | 0% |

结论很干净：**协调收益几乎全部来自物流侧"自私选最快、社会最优选最便宜"这一处分歧**；财务在两个组合里选同一策略，它的系统效用在差值里整项抵消。

## 扫描 1 · 单参数扰动（OAT，66 次）

每个权重独立乘 ×0.50 / 0.75 / 0.90 / 1.10 / 1.25 / 1.50。

| 权重 | 收益极差 | 区间 | 组合翻转 |
|---|---:|---|---:|
| logistics_sys_cost_efficiency | 26.15 | [5.17, 31.32] | 0/6 |
| logistics_sys_speed | 11.67 | [12.41, 24.08] | 0/6 |
| procurement_own_coverage | 9.72 | [18.25, 27.97] | 0/6 |
| procurement_sys_cost_efficiency | 4.69 | [14.49, 19.18] | 1/6 |
| procurement_sys_coverage | 3.76 | [14.49, 18.25] | 1/6 |
| procurement_own_speed | 0.00 | [18.25, 18.25] | 0/6 |
| logistics_own_speed | 0.00 | [18.25, 18.25] | 0/6 |
| logistics_own_availability | 0.00 | [18.25, 18.25] | 0/6 |
| finance_sys_service | 0.00 | [18.25, 18.25] | 0/6 |
| finance_sys_own | 0.00 | [18.25, 18.25] | 0/6 |
| finance_own_scale | 0.00 | [18.25, 18.25] | 0/6 |

**11 个权重里有 6 个对协调收益完全无影响**，两个机制：

1. **差值抵消**——`finance_sys_*`、`finance_own_scale` 影响财务的效用值，但财务在自私组合与最优组合中选同一策略，整项在相减时消掉。
2. **argmax 不变**——`procurement_own_speed`、`logistics_own_*` 只参与 own_utility，单独缩放不改变自私选择的排序，自私组合不变；而 own_utility 根本不进入 system_utility 的求和。

66 次扰动中收益全部为正（最小 5.17），最优组合仅 2 次翻转，都发生在 `procurement_sys_*` ×1.5（采购从"应急最大化供给"退回"多源联合补货"，收益降到 14.49）。

## 扫描 2 · 凸组合再分配（pair，55 次）

对 5 组"和固定、内部再分配"的权重对（如 procurement_own 的 coverage/speed），把左项份额从 0.0 扫到 1.0，步长 0.1。

- 55 次收益全部为正，区间 **[3.76, 47.35]**，均值 18.83。
- 组合翻转 7 次，出现 4 种不同的最优组合。
- 极端点 3.76 出现在物流侧系统效用完全倒向 speed（cost_efficiency 归零）时——此时物流的自私最优与社会最优重合，只剩采购那 3.76。这与上面的归因表完全自洽。

## 扫描 3 · 联合随机扰动（joint，500 次，seed=20260727）

11 个权重**同时**各自乘 uniform(0.5, 1.5)。

| 分位 | 协调收益 |
|---|---:|
| min | 0.00 |
| P5 | 4.41 |
| P25 | 12.01 |
| **P50** | **18.02** |
| P75 | 24.70 |
| P95 | 32.06 |
| max | 41.35 |

- **中位数 18.02，与基线 18.25 几乎重合**——说明基线不是被挑出来的有利点。
- 收益 > 0 占 **497/500 = 99.4%**；收益 ≥ 5 占 **94.0%**。
- 3 次收益为 0（draw 41 / 166 / 388）：自私组合恰好就是社会最优，协调无事可做。**没有一次为负**——如前所述这是构造性的。
- 出现 6 种不同的最优组合，133/500 次发生翻转。

## 可以对外说的三句话

1. **幅度是稳健的**：11 个权重同时在 ±50% 内随机扰动 500 次，协调收益中位 18.02、P5 4.41，与基线 18.25 一致——这个数不是把系数调出来的。
2. **符号不算成绩**：收益非负是构造性的（自私组合恒在可行集内），我们不拿它当证据。最坏情况是"协调无价值"（3/500），不会是"协调有害"。
3. **来源是可指认的**：18.25 里 14.49 来自物流的"最快 vs 最便宜"分歧，3.76 来自采购，财务为 0。敏感性排序也印证这一点——`logistics_sys_cost_efficiency` 是影响最大的单一权重（极差 26.15），而 6 个权重完全不影响结果。

## 已知局限

- 只在**固定演示场景**上做，未在企业场景各 `event_id` 上重复。跨场景的稳健性未验证。
- 扰动是**乘性**的，未考察权重符号翻转或超出 ±50% 的区域。
- 未做方差分解（Sobol 等全局敏感性指标），OAT + 联合抽样只能给出幅度区间与粗略归因，不能给出严格的方差贡献率。
