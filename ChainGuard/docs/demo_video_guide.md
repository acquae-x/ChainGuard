# 5 分钟实测演示视频录制指南

目标不是"把功能演一遍",而是让观看者相信**这些数字是真的**。因此本脚本的每一段
都落在"可当场复算"上——凡是不能现场验证的内容一律不进视频。

---

## 一、录制前准备（务必提前做完，不要在镜头前做）

### 1. 环境自检

```powershell
.\start-demo.ps1
```

等待出现服务就绪提示后访问 `http://127.0.0.1:8000`，确认能登录。**录制前重启一次**，
保证是干净状态。

### 2. 关键：先导入企业演示数据

**默认演示租户只有 1 个可计算物料**，样本量不足 8，节点健康面板会显示
「已回退为专家阈值，当前等价于仅绝对红线生效」——**数据驱动阈值这条能力在镜头前
将完全看不见**。

要展示双轨阈值，必须先导入企业演示数据集（`demo_assets/enterprise/csv/`，含 240 个
物料），导入后相对轨才会激活、界面才会显示「由本批 N 个物料的风险分布推导」。

> 如果时间不允许导入，请**不要**在视频里声称系统"自动学习阈值"——按界面实际显示
> 的口径讲：样本不足时诚实回退。这本身是可讲的亮点，但不能讲反。

### 3. 账号与限流

演示账号密码统一 `Demo@2026`。**登录接口限流 5 次/分钟**，切换角色演示时请预留间隔，
否则第 6 次登录会静默失败——这在镜头前很难解释。

建议提前在两个浏览器配置文件里各登录一个角色（管理员 + 一线角色），录制时切窗口
而不是反复登录。

### 4. 录制设置

- 分辨率 1920×1080，浏览器缩放 100%，隐藏书签栏
- 关闭所有通知（微信、邮件、系统更新）
- 准备一个终端窗口（用于复算演示），字号调大到后排能看清

## 二、5 分钟脚本（含精确时间分配）

### 0:00–0:25　开场：立住立场

**画面**：PPT 封面 或 系统登录页

**口播**：
> ChainGuard 是供应链中断应急决策系统。它和一般的大模型应用有一个本质区别：
> 决策链上每一个数字都由确定性代码算出，可以现场复算；大模型只负责把算好的结论
> 改写成通顺中文，不参与任何决策。接下来五分钟，我会把这句话验证给各位看。

---

### 0:25–1:15　风险发现：从监控到可解释

**画面**：登录 → 工作台 → 供应链节点健康面板

**操作**：
1. 指出四色计数（异常/预警/健康/数据不足）
2. 展开一个异常物料的「异常原因」列
3. **重点停留**：每条原因都带观测值、阈值、判据来源（`expert_default` / `calibrated`）

**口播**：
> 系统不是给一个"高危"的结论就完了。每一条判定都写清楚了：观测到的值是多少、
> 用的哪条阈值、这条阈值是专家红线还是数据推导出来的。这一列叫判据来源，
> 它决定了这个结论能不能被审计。

---

### 1:15–2:00　双轨阈值：一个关键工程判断

**画面**：节点健康面板下方的阈值来源说明行

**操作**：指着那行字念出来，然后展开某个物料的关键字段，指出「绝对轨判定」与
「相对轨判定」两个结论。

**口播**：
> 阈值有两条轨：绝对红线，和从本批数据分布推导出来的相对离群线，取更严的那个。
> 为什么不能只用数据驱动的那条？因为它是相对量——如果全线都告急，均值被抬高，
> 真正的高危节点反而不报警了。所以必须有绝对红线兜底。反过来，全线都健康时，
> 批内分数最高的那个也不该被判成高危，所以相对轨设了绝对地板。
> 这两个失效模式，我们都写了测试锁死。

> **若未导入企业数据**：改口播为——"当前租户物料数不足 8 个，系统如实显示已回退
> 为专家阈值。它不会在样本不够时假装自己在做数据驱动。"

---

### 2:00–3:00　决策链：多 Agent 到人工确认

**画面**：风险 → 创建应急事件 → 决策推演详情（DecisionTrace）

**操作**：
1. 触发/打开一次决策，展示辩论过程、仲裁结论
2. 展示策略组合 Pareto 前沿、约束违反
3. 展示敏感性曲线（库存 vs 风险指数）
4. **落点**：人工确认闸门

**口播**：
> 采购、物流、财务三个 Agent 各自出方案，系统穷举 3×3×3 共 27 种组合，在约束内
> 选系统效用更高的。冲突和折中过程全部留痕。最后这一步是人工确认——系统给建议，
> 人承担执行责任，这条边界是写进产品的，不是一句口号。

---

### 3:00–3:40　可审计：哈希链与审计动态

**画面**：设置 → 审计日志（或工作台的最近审计动态）

**口播**：
> 每一条审计记录都带前一条的哈希，构成哈希链。改动其中任意一行、或者删掉一行，
> 校验都会失败。对制造企业来说，这是能不能进采购流程的硬指标。

---

### 3:40–4:30　现场复算：把数字砸实

**画面**：切到终端

**操作**：真实执行，让输出滚出来

```bash
python -c "from src.benchmark import run_baseline; print(run_baseline())"
```

**口播**：
> 刚才界面上的风险指数 70.25、27 种可行组合，都可以在这里复算。同一个输入永远得到
> 同一个输出——我们测过连续 10 次完整决策链，中位耗时 1314 毫秒，相对波动 0.93%，
> 说明整条链没有随机成分。

（如时间紧张，可只展示已准备好的终端输出截图，但**必须是真实跑出来的**。）

---

### 4:30–5:00　收尾：边界与诚实

**画面**：PPT「已知边界」页 或 源码中的 `docs/experiments/failed/` 目录

**口播**：
> 最后说三件我们没做到的事：并发压测没做，当前时延不能外推为生产 SLA；
> 决策质量还没有在真实生产数据上验证过；密钥目前还在环境变量里，KMS 接口已经留好
> 但没有接。我们做过的实验里，有两个是负结果——权重校准在现有样本量下没有跑赢
> 专家权重，主动多信号扫描误报太高，这两份报告都原样保留在源码里。
> 能算的都算出来，算不出来的说清楚。

## 三、录制纪律（这几条比脚本更重要）

| 纪律 | 原因 |
|---|---|
| **只念界面上真实显示的内容** | 一旦口播与界面不符，可信度立刻崩塌 |
| **不要说"系统会自动学习/自动优化"** | 权重校准是建议制，必须人工确认才生效 |
| **不要承诺未实测的性能数字** | 并发、吞吐、多租户压测都没做 |
| **复算环节必须真跑** | 用截图代替也可以，但必须是真实跑出来的 |
| **出错不要慌，如实说** | 现场出错时说明原因，比假装无事更可信 |

## 四、常见翻车点

1. **登录限流**：连续登录超过 5 次/分钟会静默失败。预先登录好，别在镜头前反复登。
2. **首屏加载**：演示态由 FastAPI 直接托管前端构建产物，不起 dev server，不会现编译。
   但首次访问仍需几秒，录制时先访问一次预热。
3. **端口占用**：录制前确认 8000 未被占用（中断过的门禁可能残留进程占用 8420，
   与演示端口不冲突，但仍建议清干净）。
4. **演示数据标记**：租户带演示数据标记，界面顶部会有提示条。不要试图隐藏它——
   这是诚实标注，评委看到反而是加分。

## 五、如果只有 3 分钟

按此优先级砍：

1. 保留：开场立场（0:25）+ 双轨阈值（0:45）+ 决策链与人工确认（1:00）+ 收尾边界（0:30）
2. 砍掉：审计哈希链、现场复算终端环节（改为口头一句"这些数字可以现场复算"）
3. **绝不砍**：人工确认闸门、已知边界——这两段是可信度的来源
