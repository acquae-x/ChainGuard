# ChainGuard 5 分钟演示视频旁白稿

> 逐步点击、画面确认和异常分支请使用 [操作型演示脚本](demo_video_operation_script.md)。

> 适用场景：项目路演、比赛答辩、产品汇报  
> 建议语速：每分钟 220～240 字  
> 画面规格：1920×1080，浏览器缩放 100%

## 0:00–0:20　开场

**画面**

- ChainGuard 标题页，随后切入系统登录页。
- 屏幕字幕：`供应链中断应急决策系统`

**旁白**

> 当港口停运、供应商停产或关键物料延期时，企业真正缺少的往往不是一条风险提醒，而是一套能够解释、执行和追溯的应急方案。ChainGuard 面向制造企业，把风险发现、多方提案、约束仲裁、人工审批和审计留痕串成一条完整的决策链。

## 0:20–1:05　发现风险

**画面**

- 登录系统，进入工作台。
- 镜头停留在“节点健康”面板。
- 依次高亮异常、预警、健康和数据不足数量。
- 展开一个异常物料的原因详情。

**旁白**

> 系统首先汇总库存、订单、供应商、运输和外部事件数据，对供应链节点持续进行风险计算。这里不仅显示异常等级，还会给出观测值、触发阈值和判据来源。以这个物料为例，我们可以直接看到库存支撑时长、订单覆盖率以及风险指数为什么越线。风险结论不再是一个黑盒标签，而是一组可以核对的事实。

**屏幕字幕**

`观测值 + 阈值 + 判据来源 = 可解释风险`

## 1:05–1:40　双轨阈值

**画面**

- 展示节点健康面板中的阈值来源说明。
- 高亮“绝对轨判定”和“相对轨判定”。
- 若企业数据尚未导入，则停留在“样本不足，回退专家阈值”的提示上。

**旁白**

> ChainGuard 同时使用两类阈值：一类是专家设定的绝对红线，另一类来自当前批次数据分布的相对离群线，并取更严格的结果。绝对红线确保全线告急时不会漏报；相对阈值则帮助发现尚未触碰红线、但已经明显偏离同类节点的风险。当样本量不足时，系统会明确回退到专家阈值，不会给出缺少数据依据的结论。

## 1:40–2:45　生成应急方案

**画面**

- 从风险记录点击“创建应急事件”。
- 打开事件详情，点击“生成决策方案”。
- 展示采购、物流和财务三个 Agent 的提案。
- 打开“决策推演”，依次展示辩论记录、约束违反、Pareto 前沿和敏感性曲线。

**旁白**

> 风险确认后，可以一键创建应急事件。采购 Agent 关注供应可得性和交期，物流 Agent 评估运输路径与时效，财务 Agent 控制成本与现金占用。三个角色分别给出候选策略，系统再穷举三乘三乘三，共二十七种组合，过滤掉违反预算、产能和交付约束的方案，并对剩余组合进行效用比较。
>
> 整个过程不会只留下一个答案。我们可以回看各方观点、方案为什么被排除、成本与交付如何权衡，也可以通过敏感性曲线观察库存变化对风险指数的影响。

**屏幕字幕**

`多角色提案 → 约束校验 → 组合仲裁 → 推荐方案`

## 2:45–3:25　人工审批与任务落地

**画面**

- 选中推荐方案并进入审批。
- 展示风险等级、成本影响和审批意见。
- 批准后切换到任务列表，展示拆分出的采购、物流、仓储等执行任务。

**旁白**

> ChainGuard 提供建议，但不替企业承担执行责任。高风险事件或未收敛方案会强制进入人工审批。审批人可以查看依据、调整方案、批准或驳回。方案获批后，系统将行动拆分到采购、物流、仓储、计划和销售等角色，形成可跟踪的执行任务，让决策真正进入业务流程。

**屏幕字幕**

`系统给建议，人负责确认`

## 3:25–4:00　审计与追溯

**画面**

- 打开“设置 → 审计日志”。
- 展示事件创建、方案生成、审批和任务状态变化记录。
- 高亮操作者、时间、动作及哈希字段。

**旁白**

> 从风险发现到审批执行，每一步都会写入审计日志。记录包含操作者、时间、动作和前序哈希，首尾相连形成哈希链。如果中间记录被修改或删除，完整性校验就会失败。这让一次应急决策不仅能够复盘，也能够接受审计。

## 4:00–4:35　现场复算

**画面**

- 切换到终端，执行：

```powershell
Set-Location "D:\github_projects\Chainguard\ChainGuard"
python -c "from src.benchmark import run_baseline; print(run_baseline())"
```

- 高亮输出中的：
  - `inventory_risk_index: 70.25`
  - `feasible_count: 27`
  - `debate_converged: True`

**旁白**

> 更重要的是，界面上的关键数字可以现场复算。当前基准场景得到的库存风险指数是七十点二五，可行组合数是二十七，辩论结果已经收敛。同一份输入会得到同一份计算结果。大模型只负责将已经算出的结论组织成自然语言，不参与风险指数、约束判断和方案排序。

## 4:35–5:00　收尾

**画面**

- 回到工作台全景。
- 最终字幕依次出现：`可解释`、`可执行`、`可审计`、`可人工确认`。

**旁白**

> ChainGuard 目前仍有清晰边界：现有性能数据不能直接外推为生产环境 SLA，方案质量还需要真实企业数据持续验证，生产密钥也需要接入 KMS 管理。但它已经证明了一件事：供应链应急决策可以不依赖黑盒拍板，而是建立在数据、约束、责任和证据之上。能计算的现场复算，不能确定的明确交给人。

## 录制前检查

- 使用 API 模式录制，提前启动并预热页面。
- 如需展示双轨阈值，先导入企业演示数据；否则按“样本不足，回退专家阈值”的实际提示讲解。
- 提前登录管理员和业务角色，避免录制时频繁登录触发限流。
- 终端复算必须真实执行，不使用手工伪造输出。
- 只讲当前界面真实显示的数据，不承诺未经验证的并发或生产性能。
