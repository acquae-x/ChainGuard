# ERP 字段映射（E01/E02）

运行时唯一映射源是 `config/erp_mapping.yaml`；CSV 导入和 ERP 手动同步都通过同一份 C2 adapter 使用它。`config/erp_mapping.template.json` 是便于对接方复制、评审或转换工具读取的等价最小模板，不能与 YAML 同时作为运行时来源。

最小闭环包含 `material`、`supplier`、`supplier_material`、`customer`、`order`、`order_line` 和 `inventory`。同步时应按这个顺序选择，以满足租户内关系的外键约束。

使用方式：

1. 从 YAML 或 JSON 模板复制到客户的变更评审材料中，并保留 `version`。
2. 仅在 `fields` 中配置直接同名或重命名字段；在 `converts` 中声明类型转换。目标列以实体模型为准。
3. `required` 中的业务键缺失时该行会写入拒绝清单，不会猜测补值。未声明的列进入 `extra`。
4. 不得移除 `sensitive_columns`。命中敏感列的源行不会落库，也不会进入 `extra`。
5. 通过代码评审后再替换 `config/erp_mapping.yaml` 并运行 C2/ERP 回归测试。

## 页面内编辑

「系统设置 → 集成 → ERP 字段映射」提供按实体分组的映射编辑器，权限收敛为 `settings:manage`，
读写均按租户隔离；没有该权限的用户既不能读取也不能修改映射内容。

- 保存的映射存为租户级版本（`tenant_configs.config_type = erp_field_mapping`），
  **本租户的下一次 ERP 同步立即按新映射执行**；同步历史与审计记录所用映射的来源、版本、
  修改人和修改时间。
- 保存前做结构校验、重复目标字段校验、必填/业务键校验；校验失败不写入任何版本。
  危险但合法的改动（移除敏感列保护、解除订单行禁止列、未声明列改为 reject、业务键换源列）
  以警告形式二次确认后才落库。
- 租户映射不可用时，同步以 `CG-2810` 明确失败并说明原因，**不会静默回退到内置映射**；
  「恢复内置映射」是唯一的显式回退入口。
- 源字段目录来自对 ERP 的真实采样，需要先保存连接并通过连通测试；未保存、未测试或采样为空
  时分别返回 `CG-2803` / `CG-2813` / `CG-2814`，不猜字段。
- CSV / OCR 导入仍使用内置映射文件，不受租户 ERP 映射影响。

凭证属于“系统设置 → 集成”的租户配置，不属于映射文件；不得写入 YAML、JSON、日志、审计详情或同步历史。
